Alva provides a REST API for connecting your CRM data to other applications, automation platforms such as Zapier, and your own workflows.

## Overview

- **Base URL:** `https://app.alvahq.com/api/v1`
- **Format:** JSON request and response bodies
- **Authentication:** Bearer token (API keys)
- **Rate limit:** 100 requests per minute per API key
- **Specification:** OpenAPI 3.1

## Authentication

Every request needs an API key, sent as a Bearer token. Admins create keys in **Settings → Developer**.

```bash
curl -H "Authorization: Bearer alva_sk_your_key_here" \
  https://app.alvahq.com/api/v1/me
```

### API key format

Keys follow the format `alva_sk_` followed by 32 hexadecimal characters.

The full key is shown **once**, when you create it. Store it securely — it can't be retrieved later.

### What a key can do

A key never grants more than the person who created it can do in Alva. On every request, Alva checks the creator's current permissions on the account as well as the key's scopes:

- If the creator has since become read-only on the account, write requests return `403`.
- If the creator no longer has access to the account, the key stops working.
- When creating a key, you can only choose scopes you're allowed to perform yourself; the others are shown but disabled.

A key's scopes are a ceiling, not a guarantee.

### Scopes

| Scope | What it allows |
|-------|---------------|
| `companies:read` | List and get companies |
| `companies:write` | Create, update, and delete companies |
| `contacts:read` | List and get contacts |
| `contacts:write` | Create, update, and delete contacts |
| `deals:read` | List and get deals (including methodology data) |
| `deals:write` | Create, update, and delete deals |
| `activities:read` | List and get activities |
| `activities:write` | Create and update activities |
| `pipeline:read` | List pipeline stages and methodologies |
| `custom_fields:read` | List and get custom field definitions |
| `custom_fields:write` | Create, update, and delete custom field definitions |
| `email_templates:read` | List and get email templates and template groups |
| `email_templates:write` | Create, update, and delete email templates and template groups |
| `bdr_agents:read` | List BDR agents |
| `bdr_agents:write` | Assign a company to a BDR agent |

## Paths

Lists and creates use the **plural** path (for example `/api/v1/companies`). Operations on one existing record use the **singular** path with the record's id (for example `/api/v1/company/:id`).

A create sent to the singular path without an id (for example `POST /api/v1/company`) also works. A `GET`, `PATCH`, or `DELETE` on a singular path without an id returns `404`.

The endpoint pages on this tab are generated from the live specification at `https://app.alvahq.com/api/v1/openapi`. That is the same document as the API Console in Alva. When the API changes in production, these pages change with the next docs deploy.

## Pagination and sorting

List endpoints take:

- `page` — page number (default `1`)
- `limit` — items per page (default `25`, maximum `100`)
- `sort` — field and direction, for example `sort=createdAt:desc`

## Errors

Errors share one format:

```json
{
  "error": "Error Type",
  "message": "Human-readable description",
  "details": { "field": ["Validation message"] }
}
```

Validation errors return `422` with a `details` entry for each field that failed.

## Rate limiting

Every response includes rate limit headers:

| Header | Description |
|--------|------------|
| `X-RateLimit-Limit` | Maximum requests per minute |
| `X-RateLimit-Remaining` | Requests remaining in the current window |
| `X-RateLimit-Reset` | When the limit resets (Unix timestamp) |

If you go over the limit, you receive `429 Too Many Requests` with a `Retry-After` header.

## Managing API keys

Go to **Settings → Developer** (admin only) to:

- Create keys with a name, the scopes you need, and an optional expiry date
- See active keys with their prefix, scopes, and when they were last used
- Revoke keys you no longer need

You can also ask [Alva](/ai-assistant/talking-to-alva) to list or revoke your API keys. To create a key, Alva sends you to **Settings → Developer**, because the key is shown only once on screen.

## API Console

The interactive API Console at [app.alvahq.com/developers/api-reference](https://app.alvahq.com/developers/api-reference) documents every endpoint and lets you send test requests. You can also open it from **API Console** in **Settings → Developer**.

- **Anyone** can read the documentation. To send a test request without signing in, paste a full API key.
- **Signed in**, you pick one of your existing keys instead of pasting it. Test requests run with that key's scopes and your permissions, and the key itself is never shown in the console.

## OpenAPI specification

The full OpenAPI 3.1 specification is available at:

```
GET https://app.alvahq.com/api/v1/openapi
```

Use it to generate client libraries, import the API into Postman, or power other API tools. To connect Alva to Zapier or a similar platform, use a webhook or custom request step with your base URL and an API key.
